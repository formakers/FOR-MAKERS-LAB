# 1. 일반 웹캠과 Depth 카메라의 차이

일반 웹캠은 기본적으로 RGB 영상을 제공한다.

RGB 영상으로 알 수 있는 대표적인 정보는 다음과 같다.

-   물체의 색
-   물체의 모양
-   화면에서의 위치
-   YOLO 같은 AI를 사용했을 때 물체의 종류

하지만 일반적인 단일 RGB 영상만으로는 물체가 카메라에서 실제로 몇 cm
떨어져 있는지를 직접 측정하기 어렵다.

Depth 카메라는 여기에 **거리 정보(Depth)**를 추가한다.

쉽게 표현하면:

> 일반 카메라는 "무엇이 보이는가?"를 본다.\
> Depth 카메라는 "무엇이 보이고, 얼마나 떨어져 있는가?"까지 측정한다.

Depth 영상에서는 픽셀마다 카메라와 물체 사이의 거리에 해당하는 값을 얻을
수 있다.

이 때문에 Depth 카메라는 로봇 비전에서 매우 유용하다.

# 2. 오늘 만든 시스템의 전체 구조

``` text
3D Depth Camera
       │
       ├── RGB Frame
       │      ↓
       │    YOLO
       │      ↓
       │   CUP Detection
       │      ↓
       │  Bounding Box
       │
       └── Depth Frame
              ↓
       컵 영역의 거리 측정
              ↓
        X · Y · Z 계산
              ↓
      Width · Height 계산
              ↓
       3D Box 시각화
```

한 문장으로 정리하면:

> **YOLO는 물체가 무엇인지 찾고, Depth 카메라는 그 물체가 3차원 공간의
> 어디에 있는지를 측정한다.**

# 3. RGB 실시간 영상 입력

첫 단계는 카메라에서 RGB 프레임을 계속 받아오는 것이다.

영상은 정지 사진 한 장이 아니라 초당 여러 장의 이미지가 연속으로
들어오는 구조다.

프로그램은 보통 다음 과정을 반복한다.

``` text
프레임 받기
→ 이미지 변환
→ YOLO에 전달
→ 결과 그리기
→ 화면 표시
→ 다음 프레임
```

이 반복이 충분히 빠르게 이루어지면 사람 눈에는 실시간 영상처럼 보인다.

------------------------------------------------------------------------

# 4. YOLO Object Detection

YOLO는 입력된 RGB 영상에서 물체를 찾는다.

오늘의 목표는 **컵(CUP)** 이었다.

YOLO가 컵을 찾으면 보통 다음과 같은 정보를 얻는다.

``` text
Class       : cup
Confidence  : 0.xx
Bounding Box: x1, y1, x2, y2
```

## Confidence란?

Confidence는 AI가 해당 물체를 얼마나 확신하는지를 나타내는 값이다.

예:

``` text
0.90 → 매우 높은 신뢰도
0.50 → 중간 정도
0.15 → 낮은 결과까지 표시
```

오늘 실험에서는 컵을 조금 더 민감하게 찾기 위해 Confidence 임계값을
낮추는 작업도 했다.

개념적으로는 다음과 같다.

``` python
CONFIDENCE = 0.15
```

값을 너무 낮추면 컵이 아닌 물체도 컵으로 판단하는 오검출이 증가할 수
있다.

------------------------------------------------------------------------

# 5. Bounding Box

YOLO가 물체를 찾으면 화면상의 위치를 사각형으로 표현할 수 있다.

``` text
(x1, y1) ┌────────────┐
         │            │
         │    CUP     │
         │            │
         └────────────┘ (x2, y2)
```

이 박스는 단순한 장식이 아니다.

박스를 이용하면 다음 값을 얻을 수 있다.

``` text
중심 X = (x1 + x2) / 2
중심 Y = (y1 + y2) / 2

픽셀 폭   = x2 - x1
픽셀 높이 = y2 - y1
```

즉 AI가 "컵이 있다"고 판단한 영역을 사람이 직접 눈으로 확인할 수 있게
된다.

------------------------------------------------------------------------

# 6. Center Pixel

컵 Bounding Box의 중심점을 계산하면 대표적인 픽셀 위치를 얻을 수 있다.

``` python
center_x = (x1 + x2) // 2
center_y = (y1 + y2) // 2
```

컵을 좌우로 움직이면 `center_x`가 변하고, 위아래로 움직이면 `center_y`가
변한다.

이 중심 픽셀은 Depth 정보와 연결하는 중요한 기준점이 된다.

------------------------------------------------------------------------

# 7. Depth Measurement

YOLO는 RGB 영상에서 컵을 찾는다.

그러나 거리 정보는 Depth 프레임에서 가져온다.

따라서 핵심은:

``` text
RGB에서 찾은 컵 위치
          ↓
Depth 영상의 대응 위치
          ↓
거리 값 읽기
```

이다.

예를 들어 컵 중심에 대응하는 Depth가 0.48 m라면:

``` text
Distance Z ≈ 48 cm
```

처럼 표현할 수 있다.

실제 시스템에서는 한 픽셀만 사용하는 것보다 컵 내부의 작은 영역에서
유효한 Depth 값들을 모아 중앙값(median) 등을 사용하는 방식이 노이즈에 더
강할 수 있다.

------------------------------------------------------------------------

# 8. RGB와 Depth 정렬

RGB 센서와 Depth 센서가 물리적으로 서로 다른 위치에 있을 수 있기 때문에
두 영상의 픽셀이 처음부터 완벽히 일치한다고 가정하면 안 된다.

그래서 카메라 SDK가 제공하는 **Alignment(정렬)** 기능이 중요하다.

개념은 다음과 같다.

``` text
RGB의 CUP 위치
       ↓
RGB ↔ Depth 정렬
       ↓
동일한 실제 물체의 Depth 위치
```

정렬이 맞지 않으면 컵을 찾았는데 배경의 거리 값을 읽는 문제가 발생할 수
있다.

------------------------------------------------------------------------

# 9. X · Y · Z 3차원 위치

Depth 카메라의 가장 중요한 부분 중 하나다.

영상의 픽셀 좌표 `(u, v)`와 거리 `Z`, 그리고 카메라 내부 파라미터를
이용하면 카메라 기준 3차원 위치를 계산할 수 있다.

대표적인 핀홀 카메라 모델에서는 개념적으로 다음 관계를 사용한다.

``` text
X = (u - cx) × Z / fx
Y = (v - cy) × Z / fy
Z = Depth
```

여기서:

``` text
u, v   : 영상의 픽셀 좌표
cx, cy : 카메라의 중심점
fx, fy : 카메라 초점거리 관련 내부 파라미터
Z       : 카메라에서 물체까지의 깊이
X       : 좌우 위치
Y       : 상하 위치
```

따라서 컵을 실제로 움직이면 X, Y, Z 값도 실시간으로 변화한다.

------------------------------------------------------------------------

# 10. 픽셀을 cm로 바꾸는 원리

화면에서 컵의 폭이 100 pixel이라고 해서 실제 폭이 항상 같은 것은 아니다.

같은 컵도 카메라 가까이에 있으면 크게 보이고 멀리 있으면 작게 보인다.

그래서 픽셀 크기만으로 실제 cm를 계산해서는 안 된다.

Depth 값과 카메라 내부 파라미터를 함께 사용한다.

개념적으로:

``` text
실제 폭 ≈ 픽셀 폭 × Z / fx
실제 높이 ≈ 픽셀 높이 × Z / fy
```

미터 단위 결과를 cm로 바꾸면:

``` python
width_cm = width_m * 100.0
height_cm = height_m * 100.0
```

오늘 화면에 표시한 `WIDTH`, `HEIGHT`가 이 아이디어를 이용한 값이다.

------------------------------------------------------------------------

# 11. 왜 실제 줄자로 비교했는가?

컴퓨터가 숫자를 출력한다고 해서 그 숫자가 항상 정확한 것은 아니다.

그래서 실제 컵의 크기를 줄자로 측정하고 프로그램 결과와 비교하는 과정이
중요하다.

확인해야 할 항목:

-   카메라와 컵 사이 거리
-   컵의 실제 폭
-   컵의 실제 높이
-   프로그램이 계산한 폭과 높이
-   컵을 가까이/멀리 했을 때 값의 변화
-   컵을 기울였을 때 오차 변화

이 과정이 바로 **검증(Validation)** 이다.

------------------------------------------------------------------------

# 12. 컵을 기울이면 크기가 달라지는 이유

현재의 Width와 Height는 완전한 3D 스캔 치수가 아니라 YOLO의 2D Bounding
Box와 Depth를 이용한 추정값이다.

컵을 비스듬하게 놓으면 영상에 투영된 모양이 달라지고 Bounding Box도
변한다.

따라서 계산된 폭과 높이도 달라질 수 있다.

정밀한 실제 3D 크기가 필요하다면 다음 단계가 필요하다.

-   컵 영역의 Depth 포인트 전체 수집
-   Point Cloud 생성
-   배경 제거
-   물체 표면 분리
-   3D 좌표의 최소/최대 범위 계산
-   필요하면 Oriented 3D Bounding Box 적용

------------------------------------------------------------------------

# 13. 2D Bounding Box와 3D Bounding Box의 차이

## 2D Bounding Box

``` text
┌───────────┐
│    CUP    │
└───────────┘
```

RGB 영상 위에서 물체가 차지하는 영역을 나타낸다.

## 3D Bounding Box

개념적으로는 물체의:

``` text
X 방향 폭
Y 방향 높이
Z 방향 깊이
```

까지 포함한 공간 박스다.

오늘 화면에 표현한 입체 박스는 3D 정보를 사람이 이해하기 쉽게 보여주는
**시각화** 성격도 있다.

진짜 공간상의 3D Bounding Box를 얻으려면 컵 표면의 여러 Depth 포인트를
이용해 Z 방향 두께까지 계산하는 것이 좋다.

# 17. OBS와 함께 사용하기

Python이 Depth 카메라를 직접 사용하고 있는 상태에서 OBS가 같은 V4L2
카메라 장치를 동시에 열면 충돌하거나 timeout이 발생할 수 있다.

오늘 확인한 대표 로그:

``` text
v4l2-input: /dev/video8: select timed out
v4l2-input: /dev/video8: failed to log status
```

안정적인 구조는 다음과 같다.

``` text
Depth Camera
     ↓
Python
     ↓
YOLO + Depth 결과 창
     ↓
OBS Window Capture
     ↓
녹화 / 방송
```

즉 OBS가 Depth 카메라를 다시 직접 여는 것이 아니라 Python 결과 창을
캡처하는 방식이다.

# 18. OBS Window Capture 크래시 경험

기존 OBS 환경에서는 Window Capture를 선택했을 때 프로그램이 종료되며:

``` text

```

가 발생했다.

당시 확인한 환경:

``` text
Session : X11
OBS     : 30.0.2.1-3build1
```

이후 Flatpak OBS로 전환했고 화면에서 확인된 버전은 `OBS 32.2.2`였다.

Flatpak 실행 예:

``` bash
flatpak run com.obsproject.Studio
```

실제 제작 환경에서는 OBS 버전, X11/Wayland, V4L2 장치 점유 상태를 각각
분리해서 확인하는 것이 좋다.

# 20. 바이브 코딩은 공부가 필요 없다는 뜻이 아니다

AI가 코드를 만들어준다고 해서 전문지식이 필요 없어지는 것은 아니다.

오히려 중요한 것은:

-   실행 결과를 관찰하는 능력
-   이상한 값을 발견하는 능력
-   실제 하드웨어를 이해하는 능력
-   오류 메시지를 읽는 습관
-   다음 질문을 만드는 능력
-   결과가 맞는지 검증하는 능력

이다.

따라서 바이브 코딩은:

> **공부하지 않아도 되는 방법이 아니라, 만들면서 필요한 것을 공부할 수
> 있게 해주는 방법**

이라고 보는 것이 더 적절하다.

# 21. 하드웨어와 소프트웨어의 순환

피지컬 AI와 로봇은 소프트웨어만으로 완성되지 않는다.

``` text
아이디어
   ↓
AI와 대화
   ↓
Python / ROS / AI 코드
   ↓
실제 카메라·센서·모터
   ↓
실험
   ↓
측정 데이터와 오류
   ↓
다시 질문
   ↓
코드 개선
   ↓
다시 하드웨어 테스트
```

이 순환을 반복하면서 경험치가 쌓인다.

코드를 복사해 실행하는 것보다 **왜 이런 결과가 나왔는지 이해하는
과정**이 장기적으로 더 중요하다.

# 22. 다음 단계 --- 로봇팔과 연결

오늘은 카메라 기준의 물체 위치를 얻는 단계까지 공부했다.

다음 목표는:

``` text
YOLO
 ↓
컵 인식
 ↓
Depth
 ↓
Camera X,Y,Z
 ↓
Camera → Robot 좌표 변환
 ↓
로봇팔 목표 위치
 ↓
접근
 ↓
Gripper
 ↓
Pick
```

이다.

여기서 중요한 새로운 주제는 **카메라 좌표계와 로봇 좌표계의
캘리브레이션**이다.

카메라가 말하는 `(X, Y, Z)`를 그대로 로봇팔에 보내는 것이 아니라 두
좌표계의 관계를 구해야 한다.

이것이 오늘의 3D 비전 실험이 실제 로봇 조작으로 연결되는 다음 단계다.

# 23. 오늘의 핵심 정리

오늘 구현한 시스템을 다시 한 번 정리하면:

``` text
① RGB CAMERA
   실시간 영상 입력

② YOLO OBJECT DETECTION
   컵 자동 인식

③ BOUNDING BOX
   컵 영역 시각화

④ DEPTH MEASUREMENT
   카메라 ↔ 컵 거리 측정

⑤ 3D POSITION
   X · Y · Z 위치 계산

⑥ OBJECT SIZE
   Width · Height를 cm로 추정

⑦ 3D VISUALIZATION
   물체의 위치와 크기를 입체 박스로 표현
```

그리고 전체를 한 문장으로 정리하면:

> **AI가 물체를 찾고, Depth 카메라가 3차원 정보를 측정한다.**
